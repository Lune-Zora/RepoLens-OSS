# 0.7通用修复流程验收（2026-10-30）

本次目标是让自由问题描述进入实际源码定位和验证流程，减少对日期Demo固定词汇、注释提示和测试集合的依赖。当前完整项目回归为251 passed、81 subtests passed，另有1条依赖弃用警告；原始记录见下方入口。

## 已实现

- 问题理解：模型先在不看仓库的情况下理解原始业务操作，再读取当前仓库的函数目录/实现并核对同类功能，输出原始问题解释、预期行为、检索表达、实际目标和范围判断。引用必须对应真实符号；不存在或无法确认的功能说明原因。大仓库先改写检索表达再选预算内源码，目录截断明确披露。
- 检索输入：生成报告、project-os、工具产物和独立验收目录不进入索引。索引复用改用内容SHA-256，而非仅mtime/大小。
- 当前问题测试：模型按需求、公开接口和原有测试提出具体参数与预期值，经补丁前审核、参数绑定和结构检查后冻结。结构化输出限制格式、真实路径和参数形态，不提供修复答案。若未复现，会保留已通过用例并有限地补充新输入；预期值与候选补丁保持分离。原有仓库测试与问题用例一起执行；必须复现当前问题失败，不能通过修复别的问题来冒充目标完成。
- 候选补丁：提供原始源码，避免展示行号混入from/to；校验真实路径、唯一匹配及所确认函数的AST修改范围。生成格式失败和越界原因进入后续反馈。
- 验收：原有PASS必须保持；其他已有FAIL单列，不能新增或恶化；独立验收冻结在仓库外，不进入模型或重试反馈。模型生成/审核的测试仍不是独立验证。
- Web：三个本地模型可逐请求选择，选择不修改全局环境；显示理解过程、真实模型、测试范围和失败原因；任务进行时禁用提交，后端串行修复；辅助JSON从数据集下拉剔除，待核验用黄色，不把安装向量库称为向量权重可用。
- 报告与重放：新任务测试保存在证据包主套件中，可以通过标准CLI verify完整重放；老证据保持原字节。

## 自动测试的限制与明确样例

改名并换一种中文表述的额外仓库曾出现：自动用例没有覆盖异常输入、模型给出错误期望、候选包含不允许的测试文件修改。失败均保留，不能用之前某一轮通过记录声称所有改写都稳定自动成功。

因此提供两种明确模式：自动设计/审核用例；或者调用者给出输入与期望，原样冻结。两者都执行真实补丁、原测试保持与外部独立验收；调用者提供的样例不算模型自动生成的测试。输出结构约束只限定实际文件、参数及JSON格式，不提供修复答案。

## 新版实际使用

从项目根目录运行python scripts/start_web.py，打开http://127.0.0.1:8000/。模型默认9B；独立任务下拉会填入各自仓库、问题和外部验收路径。也可自行选择仓库，自由描述实际问题；不是输入任意题目就能让不存在的功能出现。

没有独立验收时，即便自动检查通过也只给UNVERIFIED；不能为追求绿色状态删除该条件。每次使用仍需查看diff及覆盖范围。

## 边界

这是可运行的Python修复工作流，仍非任意大型仓库、任意语言或任意业务都可靠的通用自动修复系统。测试模型也会出错；复杂对象构造、异步API、外部服务、环境依赖与上下文预算可能阻塞。函数范围约束目前较保守，跨函数签名或模块初始化改动会被拒绝；不能把这种拒绝隐瞒为成功。临时副本不是操作系统沙箱。

本地GGUF原始来源等资源待确认项、最终视频、公开链接及比赛提交回执仍需分别完成，软件改造不代替这些交付事项。
