# 请求库挖掘受限说明（requests）

> 更新：2026-10-29（第三次修订）。结论：**requests 贡献 5 条修复样本**（其中 4 条来自「按时代建环境」，见第 9 节）。
> 本文记录三轮排查：为什么「装依赖」无效、归属规则错在哪、以及时代环境是怎么建起来的。

## 1. 做了什么

按要求安装了 requests 的测试依赖（其 `requirements-dev.txt` 要求）：

```bash
python -m pip install pytest-httpbin==2.0.0 "httpbin~=0.10.0" trustme
```

安装后 `pytest_httpbin` / `httpbin` / `trustme` 均可导入，我们的项目自检（`scripts/check_env.py --with-web`）与全量测试（170 passed）未受影响。

## 2. 但依赖并不是真正的障碍

装完依赖后重新挖掘：**候选数与通过数完全不变**（11 挖 1 通）。

手工复现一个失败样本，拿到了真正的错误：

```text
ImportError while loading conftest '...\tests\conftest.py'.
tests\__init__.py:8: in <module>
    from urllib3.exceptions import SNIMissingWarning
E   ImportError: cannot import name 'SNIMissingWarning' from 'urllib3.exceptions'
```

**历史提交的测试代码依赖 urllib3 1.x 的 API，而本机是 urllib3 2.x。**
`SNIMissingWarning` 在 urllib3 2.0 中被移除，导致 conftest 导入失败，pytest 直接以退出码 4（用法错误）结束——
这与被测修复本身无关。

## 3. 为什么不能简单地「只挖新提交」

requests 在 `15585909 Support missing SNIMissingWarning in tests (#6336)`（2023-01-21）加了 try/except 守卫，
之后的提交可以正常跑。但实测：

| 范围 | 提交数 | 挖掘候选 | 验证通过 |
|---|---|---|---|
| 全历史（`--max 100`） | 6000+ | 11 | 1 |
| 仅 2023-01-22 之后（浅克隆） | 128 | 2 | 1 |

**即使把范围缩到兼容之后的 128 个提交，也只有 2 条候选**——
因为 requests 的 fix 提交很少在同一次提交里同时改动源码与测试（抽样前 80 个 fix 提交，仅 11% 两者都改）。

## 4. 唯一通过验证的那条也不能用

候选：`#6628 - JSONDecodeError are not deserializable`，标注 `src/requests/exceptions.py:__init__:41`。

实际情况：该修复**新增了 `__reduce__` 方法**（新文件 44–52 行），而标注指向的 `__init__`（34–42 行）
在补丁里只是上下文行，并未被改动。

机械复核的 C4（标注函数必须被改动触及）正确地把它判为不可用。

**根因**：miner 在「纯插入 hunk」上会把插入点回退到 hunk 起始行，从而归属到前一个符号。这是已知启发式局限。

## 8. 第二次修订：那条样本为什么最终可用了

第一版结论是 0 条，因为唯一通过验证的样本被机械复核剔除：标注 `exceptions.py:__init__:41`，
而实际修复是**新增 `__reduce__` 方法**，`__init__` 只是上下文行。

修正归属规则后，该样本变为 `src/requests/exceptions.py:JSONDecodeError:31` —— 归到**外层类**。

### 为什么归到外层类是正确的

| 条件 | 说明 |
|---|---|
| 类在 buggy 版本中存在 | 定位评测是在 buggy 树上检索，目标必须存在 |
| 类的行范围包含改动 | 新增的 `__reduce__` 落在类体内，标注与改动语义一致 |
| 新方法本身不存在于 buggy 版本 | 不能作为检索目标，否则永远命中不了 |

### 规则

1. 改动落在**已有**符号内 → 用该符号；
2. 改动**新增**了符号 → 归到其在旧版本存在的外层类；
3. 都不成立 → 退回旧文件改动位置的符号。

该规则实现在 `replens/miner.py::attribute_symbol`，并由 `scripts/repair_annotations.py` 回溯应用到已有样本（本轮修正 91/98 条）。

## 9. 第四轮：按时代建环境，requests 贡献样本 1 → 5

> 上一版的结论是「装依赖没用」。这句话只对了一半：缺的不是包，是**版本矩阵**。
> 2019 年的 requests 写的是 `urllib3>=1.21.1,<1.27`，2020 年才放宽到 `<3`。

### 9.1 时代由候选自己的声明决定，不由人猜

| 步骤 | 实现 | 说明 |
|---|---|---|
| 1. 读约束 | `era_env.select_profile(repo, parent)` | 读**父提交**的 `setup.py` / `setup.cfg` / `requirements*.txt` 里的 urllib3 上界 |
| 2. 映射锁文件 | `eval/envs/urllib3-1.txt`（入库） | `urllib3==1.26.20` + pytest 7.4.4 + pytest-httpbin + trustme + pytest-mock |
| 3. 运行期依赖 | `era_env.runtime_specifiers(setup.py)` | 该提交自己的 `install_requires`（含 `requires=[...]` 写法），锁文件已钉的包以锁为准 |
| 4. 建 venv | `era_env.ensure()` | 落在用户缓存（`%LOCALAPPDATA%\\.miner_envs`），不碰全局 site-packages |
| 5. 验证 | `miner.verify_item(..., python=<venv python>)` | 验证结果里记 `env` 画像（profile / python / urllib3 / pytest） |

为什么不锁 `pytest==6.2.5`（该时代 requirements-dev.txt 的写法）：6.2.5 与本机 py3.10 的插件生态
（pytest-httpbin 2.0 / pytest-mock）组合不稳定；而**定义这个时代、导致 conftest 导入失败的约束是 urllib3 的 API**，不是 pytest。
这条取舍写在锁文件头部，评审可见。

> 上一轮「装依赖」把 greenlet 从 3.5.6 降到 2.0.2，影响本机其它工具。本轮全部装在独立 venv 里，
> 全局环境零改动——这本身就是「按时代建环境」相对「装到当前解释器」的第二个收益。

### 9.2 顺带修掉的两个验证缺陷（都会把有效候选判成失败）

| 缺陷 | 表现 | 修法 |
|---|---|---|
| pytest 节点 id 少了类名 | `tests/test_requests.py::test_proxy_...` 是 `class TestRequests` 的方法，pytest 报 `not found`（退出码 4），被记成「修复后测试未通过」 | `_test_node_spans` 沿 AST 父链拼出 `文件::类::方法` |
| pytest 输出走管道 | 超时杀掉 pytest 后仍等管道 EOF（孙进程持有句柄），`--timeout` 失效、整批验证永久挂住 | 输出重定向到文件 + `stdin=DEVNULL`，超时能真正生效 |

### 9.4 仍然存在的边界

1. **解释器版本仍需自备**（本机只有 3.10）：链路已打通但缺解释器——
   `replens era-env --profile urllib3-1 --python <旧解释器>/python` 用旧解释器建环境（目录按 py 标签区分），
   再用 `REPLENS_ERA_PY_TAG=py38 python -m replens mine ... --era-env auto` 让当前解释器复用那套环境。
   没有装旧解释器时，2018–2019 的提交能在 py3.10 跑只是运气，不能外推。
2. **首次构建需要联网**：venv 建好后再跑不需要网络。离线场景先用
   `python -m replens era-env --profile urllib3-1 --repo <仓库> --commit <提交>` 预置，
   或用 `REPLENS_ERA_ENVS` 指向已有环境目录；`--list` 可查构建状态，`--reset` 可强制重建。
3. 时代锁只覆盖 urllib3 1.x 一代。若再引入其它时代（如 pytest 3.x / py2.7 仓库），需按同样格式新增锁文件。
