# 评测口径与输入隔离（T3，2026-10-20）

本协议适用于 `python -m replens eval`、`eval/baselines.py`、`eval/ablation.py` 和 Web 定位评测。它统一定位指标与实际检索输入，供 T4 真实样本准备使用；修复成功条件仍见 [统一修复验收.md](统一修复验收.md)。

## 1. 统一的指标

`--top-k` 为 1–100 的整数。`--candidate-limit` 是传给检索器的固定符号候选预算，默认 100，必须介于 k 与 1000 之间。对照实验固定候选预算，仅改变评价 k；检索器可能追加调用图候选，JSON 的逐条记录提供实际返回数量。这个池不等于全仓库无限深度排名。

| 输出键 | 命中要求 | 排名单位与分母 |
|---|---|---|
| `hit@1`、`hit@k` | 命中任一标注文件 | 对整个返回符号池按文件首次出现去重，再取前 k；分母为全部正向样本 |
| `mrr@k` | 第一个正确文件排名 r 的倒数；k 内未命中记 0 | 与文件 hit 使用同一去重排名和同一 k；分母为全部正向样本 |
| `func_name@k` | 同一候选同时匹配路径和函数/方法短名 | 前 k 个符号；分母为至少有一条受支持函数短名标注的样本 |
| `symbol_start@k` | 同一函数/方法同时匹配路径、短名、符号起始行 ±3 | 前 k 个符号；分母为至少有一条受支持短名及行号标注的样本 |
| `refusal_rate` | 干扰样本没有证据或明确拒答 | 分母为 `expected=[]` 的干扰样本 |
| `positive_refusal_rate` | 正向样本没有证据或明确拒答 | 分母为全部正向样本 |
| `recall_evidences` | 返回池中命中标注路径，或同路径的函数短名 | 分母为全部正向样本；限定名目标不获函数命中；受候选预算限制 |

文件与符号的 k 单位不同。例如返回 `a.py:f1, a.py:f2, b.py:g` 时，文件 top-2 包含 b.py，符号 top-2 不包含 g。多条标注按完整目标逐条配对，不能用一个目标的文件和另一个目标的函数拼成命中。明确拒答的样本不会同时获得定位分数。

目前索引缺少可靠的限定名身份。`Parser.read` 这种标注仍参与文件评分，但不冒充裸名 `read` 的函数/行命中；相关样本计入 `total_qualified_unsupported`，明细列出不支持的目标。具有其他受支持短名目标的样本仍按受支持目标评分。函数起始行指标也不代表语句级缺陷定位。这两项能力属于 T5。

JSON 中保存 `counts` 的原始分子、分母、MRR 倒数和，以及逐样本文件/符号排名。某粒度没有可评样本时为 `null`，Web 显示 “—”。兼容旧调用者的 `mrr` 始终等于当前 `mrr@k`；仅当 k=5 时附带 `func@5`、`line_acc@5` 旧别名及其解释。新报告应使用上表的名称。

## 2. 基线与消融的公平性

random、grep、RepoLens 使用同一输入中的 Python 源文件与文档文件全集。random 使用与样本 ID 绑定的 5 个稳定种子，先按样本平均，不把种子计成独立 Bug；grep 统计同一文件集合中的查询 token 次数，并按路径稳定处理同分。所有方法都按文件去重，MRR 均在同一 k 截断。

RepoLens 的主评测、基线、消融共用检索适配与计分函数，检索查询仅接收 `issue`，不接收 `expected`。评测强制重建索引，避免旧索引影响结果。语义服务不可用时报告记录实际关键词模式；不会把回退结果标成已完成语义实验。消融结论只由实际运行的差值生成。

定位数据集必须为非空 JSON 数组，每条包含唯一整数/字符串 `id`、非空 `issue` 和显式 `expected` 数组。标注为 POSIX 相对路径：`path[:function[:positive_line]]`。干扰问题显式使用 `[]`。重复 ID、路径越界、错误类型或行号会在索引/模型调用前被拒绝。

```json
[
  {"id": "bug-001", "issue": "read_value 对空字符串应返回 0", "expected": ["pkg/api.py:read_value:12"]}
]
```

## 3. 两种输入模式

不提供 `--input-manifest` 时为 `repository_audit_only`：保留现有 Demo 用法，记录实际索引文件及哈希，但不认证答案隔离。标签文件即使扩展名不会被索引，也必须放在检索根之外。

提供冻结 manifest 与 `--sample-id` 时为 `isolated_allowlist`：验证允许清单、实际文件集合及字节，在临时目录中只复制允许文件，从这个小材料包建索引，结束后清理。输入根不应直接使用完整 Git 工作区，应提前整理为以下清洁目录：

```text
eval_samples/bug-001/
  sample.json              # 控制端 manifest
  control/
    labels.json            # 定位标注
    gold.patch             # 参考生产补丁
    independent.json       # 冻结独立测试（如有）
  input/                   # 仅允许的材料；不能有 .git、答案、报告或索引缓存
    pkg/api.py
    README.md
    failure.log
```

清单内文件必须全部存在，清单外文件（包括隐藏文件）会使校验失败。支持 Python 源码 `.py`，文档 `.md/.rst/.txt`，失败日志 `.log/.txt`，至少有一个 Python 源文件。路径禁止绝对路径、反斜杠、`..`、大小写冲突、符号链接/硬链接与保留目录。校验 UTF-8 和 SHA-256；输入中存在与已声明参考材料完全相同的字节，即使改名也拒绝。

失败日志当前只打包和审计，不进入源码/文档索引，也不用于定位排序（`failure_logs_used=false`）；逐 Bug 轨迹使用留待 T5/T6。严格模式暂不在这个定位材料包中执行测试；消融的 `--execution-test` 与严格清单不能同时使用。

## 4. manifest v1

以下是字段模板，尖括号占位值必须用实际提交及实际文件哈希替换。`root`、参考材料路径相对于 manifest 所在目录解析；输入文件 `path` 相对于输入 root 解析。

```json
{
  "samples": [
    {
      "sample_id": "bug-001",
      "repository": "https://github.com/owner/project",
      "source": "upstream git history",
      "license": "MIT（填写实际许可）",
      "buggy_commit": "<完整40或64位提交哈希>",
      "fix_commit": "<完整40或64位提交哈希>",
      "issue_source": "<原Issue或复现说明来源，注明人工改写情况>",
      "issue": "read_value 对空字符串应返回 0",
      "environment": {
        "os": "Windows 11",
        "python": "3.11.9",
        "dependencies": [],
        "install_command": "none"
      },
      "regression_test": {"status": "pending"},
      "before_gold_validation": {"status": "pending"},
      "independent_test_result": {"status": "pending"},
      "model_input_manifest": {
        "schema_version": 1,
        "root": "input",
        "files": [
          {"path": "pkg/api.py", "kind": "source", "sha256": "<实际64位小写SHA256>"},
          {"path": "README.md", "kind": "document", "sha256": "<实际64位小写SHA256>"},
          {"path": "failure.log", "kind": "failure_log", "sha256": "<实际64位小写SHA256>"}
        ]
      },
      "reference_materials": [
        {"path": "control/gold.patch", "role": "reference_patch", "sha256": "<实际64位小写SHA256>"},
        {"path": "control/labels.json", "role": "annotation", "sha256": "<实际64位小写SHA256>"},
        {"path": "control/independent.json", "role": "independent_test", "sha256": "<实际64位小写SHA256>"}
      ]
    }
  ]
}
```

也支持直接使用样本数组。顶层对象仅允许 `samples`。样本的上述字段均必填，只有 `candidate_trace`、`replay_artifacts` 为可选补充字段；不接受未声明字段。没有独立材料时可不列 `independent.json`，但仍应如实保留 pending 的独立结果，参考材料数组不能为空。参考角色还支持 `validation_log`、`training_material`。

PowerShell 中可逐文件取得实际哈希：

```powershell
(Get-FileHash -LiteralPath 'eval_samples/bug-001/input/pkg/api.py' -Algorithm SHA256).Hash.ToLowerInvariant()
```

`environment` 精确包含 `os/python/dependencies/install_command`，无依赖用 `[]`，无需安装用明确的 `none`。三个测试/验证结果字段为非空对象，未执行时用 `{"status":"pending"}`。填写了这些字段不等于验证完成；检查器只检验提交字符串格式，不核验 Git 提交身份或实际执行行为。重复 `sample_id` 或同仓库同 `fix_commit` 会被拒绝，避免多个描述重复计为独立 Bug。

## 5. 运行方式

在项目根目录运行。先验证元数据与材料，必要时生成可人工检查的小材料包；打包输出必须是不存在的新目录：

```powershell
python scripts/validate_sample_manifest.py eval_samples/bug-001/sample.json --audit-output reports/runs/bug-001-input-audit.json
python scripts/validate_sample_manifest.py eval_samples/bug-001/sample.json --sample-id bug-001 --pack-inputs reports/bug-001-input-package
```

包中的 `repo/` 只含允许文件，`issue.txt`、`input_receipt.json` 放在 `repo/` 之外。审计记录不能覆盖输入根中的文件、manifest 或参考材料。PASS 仅表示 schema、路径隔离、实际文件集合和哈希一致。

严格评测一次只接受一个 sample_id 对应的一条定位数据，`id` 与 `issue` 必须与冻结 manifest 一致；`repo` 参数必须指向 manifest 中的原始 input root，由评测器自行打包并清理：

```powershell
python -m replens eval eval_samples/bug-001/input --dataset eval_samples/bug-001/control/labels.json --input-manifest eval_samples/bug-001/sample.json --sample-id bug-001 --top-k 5 --candidate-limit 100 --output reports/runs/bug-001-eval.json
python eval/baselines.py eval_samples/bug-001/input --dataset eval_samples/bug-001/control/labels.json --input-manifest eval_samples/bug-001/sample.json --sample-id bug-001 --top-k 5 --candidate-limit 100 --output reports/runs/bug-001-baselines.md
python eval/ablation.py eval_samples/bug-001/input --dataset eval_samples/bug-001/control/labels.json --input-manifest eval_samples/bug-001/sample.json --sample-id bug-001 --top-k 5 --candidate-limit 100 --output reports/runs/bug-001-ablation.md
```

批量真实评测应由控制端逐样本运行，再按有效独立 Bug 汇总；不把不同 buggy 提交混在一个检索目录。基线和消融会在 Markdown 旁输出同名 JSON，主评测 JSON 包含实际模式、逐文件哈希、issue/标签哈希、选中样本规范化内容哈希和原始计数。临时输入包路径在评测结束后失效，持久结果中的文件列表及哈希用于追溯；需要保留实物时另用 `--pack-inputs`。

Web 评测页支持固定候选预算、冻结 manifest、sample ID 和自定义标签绝对路径。填入的路径都是运行 Web 服务的机器上的路径。非法输入返回明确的 400 错误；CLI 参数/输入错误退出 2，清单校验不通过退出 1。

## 6. T3 实际验证结果

2026-10-20，在工作区副本中使用 Python 3.13.6 运行 41 项专项测试，全部通过、零跳过，包括真实 FastAPI HTTP、实际索引和材料包校验。完整旧测试回归的提权请求未获批准，本轮未执行完整回归；不能把旧轮结果与本轮专项结果相加宣称全部通过。JavaScript 语法及动态指标渲染另行核验。

实际 Demo（`examples/demo_repo` + `eval/datasets/dataset.json`，20 正向 + 5 干扰，预算 100，实际模式 `bm25_callgraph`）：

| k | 文件 hit@k | mrr@k | func_name@k | symbol_start@k |
|---|---|---|---|---|
| 1 | 17/20 = 0.85 | 0.85 | 14/20 = 0.70 | 14/20 = 0.70 |
| 2 | 18/20 = 0.90 | 0.875 | 16/20 = 0.80 | 16/20 = 0.80 |
| 5 | 19/20 = 0.95 | 0.8917 | 17/20 = 0.85 | 17/20 = 0.85 |

干扰拒答 5/5，正向拒答 1/20。主评测与基线中的 RepoLens 在各 k 的文件 hit/MRR 一致。相同 k=5 下的文件对照：

| 方法 | hit@1 | hit@5 | mrr@5 |
|---|---|---|---|
| random（5 种子按样本平均） | 0.14 | 0.53 | 0.2602 |
| grep（token 次数） | 0.60 | 1.00 | 0.7250 |
| RepoLens BM25 + 调用图 | 0.85 | 0.95 | 0.8917 |

grep 的 hit@5 仍高于 RepoLens；RepoLens 的首位命中与 MRR 更高。Demo 的 20 个正向描述不等于 20 个独立真实 Bug。口径、候选预算已改变，不能把与历史报告的数字差异说成算法改进。

另用 5 个允许源文件构造小型隔离包，实际运行主评测、基线和消融，验证三入口只索引同一允许集合。该样本使用合成元数据，验证状态为 pending；它只证明隔离机制工作，不属于上游真实 Bug、自主修复成功或无语义答案泄漏的证据。

## 7. 当前边界与后续

T3 的严格模式已接入定位评测，打包 API 可供后续流程复用，但尚未统一所有自主修复模型入口。允许文档/源码/issue 中可能嵌入、改写或暗示答案，字节与路径校验无法证明其语义清洁，必须人工审阅冻结材料。公开 Bug 的预训练污染也需单独披露。

接下来执行 T4：分别恢复 tqdm、pypdf、loguru 的一个可离线复现真实 Bug，验证 buggy 失败、参考生产补丁后通过，记录提交、许可、环境、测试 ID 和独立材料。限定名身份、失败日志召回与语义候选并集在 T5 完成；模型自主修复效果与成本对照在 T6 运行。
