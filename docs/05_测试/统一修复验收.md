# 统一修复验收（T2）

CLI、Web、JSON、Markdown 和证据包共用 `replens.validation` 的结论。报告 JSON 的 `status` / `reasons` 是展示入口，`validation` 保存目标测试 ID、原有通过测试 ID 和独立验收材料哈希。

| 状态 | 含义 |
|---|---|
| VERIFIED | 主测试目标失败明确转为 PASS，原有通过测试保持 PASS，冻结独立行为验收通过，自动生成的辅助检查没有失败或无效结果 |
| UNVERIFIED | 尚无独立验收材料、没有复现失败，或定位证据不足 |
| FAILED | 目标未转为 PASS、原有通过测试退化、行为断言失败或指定补丁应用失败 |
| INVALID | 缺依赖、超时、导入/收集错误、零执行、全跳过或结构化结果不完整 |
| NO_PATCH | 有效基线下没有进入最终验收的补丁 |

`VERIFIED` 仅针对本次明确选择的测试集合；不会宣称通过未运行的测试，也不会自动代表真实数据集上的修复成功率。

## 验收规则

1. 使用当前解释器执行命令；显式 `--test-cmd` 决定框架，生成测试跟随该选择，不会静默切换框架或自动安装依赖。
2. unittest 通过自定义 TestResult 记录完整 `module.Class.test`；pytest 通过插件记录原始 nodeid（包含类名和参数）。调用、setup、teardown 失败均保留；子测试失败不能写成父测试 PASS。
3. 从修复前所有 FAIL/ERROR 测试确定目标；这些同一 ID 修复后必须是 PASS。修复前为 PASS 的测试必须仍是 PASS。SKIP、XFAIL、XPASS 和 MISSING 均不能替代 PASS。
4. 修复前后分别从源码建立干净临时副本，顺序运行并清理；修复前的测试写入不会污染修复后。原有 `run_tests` 返回临时目录的 API 仍由调用方管理目录，统一编排使用自动清理的 `run_test_suite`。
5. 补丁不能改动测试、附加验收文件或常用测试/构建配置；手动补丁也做相同检查。生成测试含有临时路径占位符时，规范化路径后比较。
6. 自动生成的行为/接口冒烟检查单独运行，不混进主测试。先检查生成代码语法；失败和无效结果保留在报告中。它们不能替代独立行为验收。
7. 独立行为用例必须由调用方预先审查，位于被修仓库之外。在索引、计划和补丁生成之前把命令和代码读入内存并计算 SHA-256；不把用例或失败日志提供给候选生成器。用例在独立副本中运行，至少一个行为目标需要实际 fail→pass，其余原有通过断言保持 PASS。

## Demo

在项目根目录运行（核心 unittest 演示不需要 pytest）：

```powershell
python -m replens run examples/demo_repo --issue "date string with surrounding whitespace fails to parse" --test-cmd "python -m unittest discover -s tests" --auto-patch --acceptance-suite examples/acceptance/demo.json --require-verified --no-provenance --format json --output reports/runs/demo_verified.json
```

pytest 已安装时也可以用 `--test-cmd "pytest tests/test_parser.py"`。主测试和独立验收可以分别采用 pytest / unittest；各自的前后命令必须保持一致。

独立材料 `examples/acceptance/demo.json` 放在 `examples/demo_repo` 外，包含制表符与换行的空白输入、闰日、非法日期和正常日期断言。材料格式：

```json
{
  "command": "python -m unittest discover -s __replens_acceptance__ -p test_behavior.py",
  "files": {
    "__replens_acceptance__/test_behavior.py": "import unittest\nfrom api import read_value\nclass Behavior(unittest.TestCase):\n    def test_whitespace(self):\n        self.assertEqual(read_value(' 2024-01-01 '), read_value('2024-01-01'))\n"
  }
}
```

此格式是测试材料接口；上方示例的导入和期望值需要按目标项目修改。只验证函数存在或签名的测试不足以验收业务修复。文件必须位于保留目录 `__replens_acceptance__/` 下，禁止绝对路径和 `..`。复杂 fixture、异步调用和外部服务需要维护者提供有效测试，不能靠生成器猜测。

省略 `--acceptance-suite` 可以生成分析和补丁报告，但主测试即使通过也只得到 UNVERIFIED。`--require-verified` 会在保存报告后，对所有非 VERIFIED 状态返回退出码 2；不加该参数时保留报告模式行为。输入文件格式错误等运行异常仍按 CLI 的异常退出处理。

Web 的“独立行为验收文件”填写服务器上仓库外的 JSON 路径，`POST /api/run` 对应字段为 `acceptance_suite`。API 返回的 `status` / `reasons` 与内嵌报告一致；无效测试显示为“无效”并展示原因。

## 自动化检查与范围

`tests/test_validation.py` 覆盖统一状态、完整测试 ID、参数化、setup/teardown、子测试、skip/xfail/xpass、收集与导入错误、超时、状态污染、保护文件、独立材料冻结、成功/失败编排、严格 CLI 和真实 Web HTTP 接口。可选依赖缺失时相关用例显式跳过；CI 安装 pytest 和 Web 测试依赖，必须实际运行。

```powershell
python -m unittest discover -s tests
python -m pytest tests -q
```

CI 除正常单元测试外，执行 VERIFIED 成功演示，并验证不提供独立材料时严格模式退出 2、报告为 UNVERIFIED。

Schema 2.0 已将生成前冻结的独立材料完整入包，`replens verify` 分别重放主测试、自动辅助检查与独立验收，并复用本页的统一结论。返回值分为材料核验、重放一致性和修复结论；重放 PASS 不会自动代表修复 VERIFIED。详见 [证据包格式与重放](证据包格式与重放.md)。当前副本执行不构成对不可信仓库代码的操作系统安全隔离，公开部署需另行处理执行环境。
