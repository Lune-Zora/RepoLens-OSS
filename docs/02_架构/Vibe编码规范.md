# Vibe编码规范

> 适用：RepoLens-OSS 全部开发会话。与[治理规则](../../project-os/治理规则.md)、[文档规范](文档规范.md)配合使用；本页只写**本项目实测有效**的做法。

## 1. 核心循环

```text
澄清 → 前置检索 → 计划 → 小步实现 → 验证 → 记录 → 复盘
```

任何一步不清晰都不动手。跳过前置检索是本项目最容易犯的错误。

## 2. 前置检索（每个需求必做）

结论必须三选一并写明理由：**复用 / 改造 / 新建**。能复用不重开发，能改造不新建。

| 检索维度 | 具体动作 |
|---|---|
| 代码功能类 | `grep` / `glob` 检索相关类、方法、模块、工具函数 |
| 接口文档 | 查 `docs/04_接口/`、`API-Web工作台.md`、既有 CLI 子命令 |
| 相似设计 | 查 `docs/02_架构/设计方案.md`、`决策记录/`、`变更日志.md`、`project-os/会话记录/` |
| 数据约定 | 查 `docs/05_测试/评测口径与输入隔离.md`、`eval/README.md` |

检索不到也要如实记录「未找到可复用资产」，不能默认从零写。

### 本项目的真实教训

> 2026-10-28 阶段 2：原计划「7 篇 `摘要.md` 内容重复需合并」。**前置检索推翻了这个判断**——
> 逐篇读完发现 7 篇各描述不同专题、内容零重叠（154B~752B）。
> 真正重复的是 `文档地图.md` 对它们的逐条复述。
> 若不做检索直接执行，会删掉有价值的专题索引。**检索成本 5 分钟，救回一次错误合并。**

## 3. 小步实现

- 一次只改一个可验证的单元；每步在当前 `S-*.md` 时间线追加一行「做了什么 / 结果」。
- 禁止一次性大改后再补测试。
- 改动涉及多处时，先改一处、跑通、再复制模式。

## 4. 验证纪律

| 改动类型 | 必须的验证 |
|---|---|
| 代码 | `python -m pytest tests/ -q`，记录 pass/fail 数字 |
| 文档 | 链接全部可解析（0 死链）+ 文档地图覆盖度 = 0 遗漏 |
| 换行/编码 | `git ls-files --eol` 分组统计，且回归测试结果不变 |
| Git 同步 | 两侧逐文件 SHA256 比对 = 0 差异 |
| 远端推送 | 全新 `clone` 后跑测试，结果须与本地相同 |

**已验证 ≠ 跑过一次。** 必须写出命令、数字和边界，例如：
'126 passed / 3 failed / 81 subtests；3 条失败为本机 anyio × typing_extensions 冲突，非代码回归'。

只写「测试通过」不算验证。

## 5. 记录纪律

- 提出需求 → 追加 `docs/99_进度/需求日志.md`（状态 doing）+ 同步 `待办.md`。
- 每步实现 / 验证 / 决策 → 追加当前 `S-*.md`，证据落 `project-os/证据/T-*/`。
- 任务完成 → 回填 `功能清单`（若有功能变化）+ `变更日志.md` + `项目状态.md`。
- 决策 → 一句话进 `project-os/决策日志.md`；需要解释取舍的写 `docs/02_架构/决策记录/ADR-NNN-*.md`。

## 6. 质量红线

| 禁止 | 说明 |
|---|---|
| 删除或弱化失败测试 | 失败就查原因，不能改成 skip 或断言放宽 |
| 跳过测试 | 包括「先提交，测试回头再补」 |
| 手写成熟库功能 | 先用标准库/既有依赖，确认没有才自己写 |
| 改完不更新文档 | 代码是真相，但文档必须跟随 |
| 不验证就宣称完成 | 见第 4 节 |
| 把历史快照当当前结论 | 历史快照必须带 `> 历史快照（截止日期）` 横幅 |
| 把 Gold/样本验证当模型自主修复 | `model_repair_credit=false` 的场景必须显式声明 |

## 7. 会话收尾

1. 回填 `S-*.md`：时间线、验证表、遗留、收尾检查。
2. 回填需求日志状态；更新项目状态与交接记录。
3. 更新 `docs/99_进度/进度交接.md` 的阶段表与阻塞项。
4. 输出三行：本次完成了什么 / 落盘到哪 / 还有什么缺口。
