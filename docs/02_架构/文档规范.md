# 文档规范

> 适用：RepoLens-OSS 全部文档。本规范整合 devskill 文档分级、中文命名、中文书写三套规则，并吸收文档标准化原则（审计、归档而非删除、代码是真相、提交前验证）。

## 1. 文档体系

| 位置 | 内容 |
|---|---|
| 根目录 | README.md（唯一英文名入口）、变更日志.md、.gitignore、.devskill |
| docs/ | 文档地图.md + 01_需求 / 02_架构（含 决策记录）/ 03_数据库 / 04_接口 / 05_测试 / 06_运维（含 运维手册）/ 07_归档 / 99_进度 |
| docs/99_进度/ | 需求日志.md、待办.md、功能清单.md、进度交接.md |
| project-os/ | 治理规则.md、项目状态.md、交接记录.md、决策日志.md、会话记录/、任务/（含 归档/）、证据/ |

## 2. 文档分级

| 等级 | 位置 | 内容 | 何时读 |
|---|---|---|---|
| L0 入口 | README.md | 项目是什么、技术栈、快速开始、文档导航 | 每次会话必读 |
| L1 路由 | docs/文档地图.md | 全部专题索引与进度 | 每次会话必读 |
| L2 摘要/专题 | docs/<专题>/ | 规则说明、Vibe编码规范、文档规范、PRD、ADR、运维手册、变更日志.md | 涉及该专题时读 |
| L3 详情 | docs/<专题>/<条目>.md | 单个表/接口/模块完整定义 | 仅修改该条目时读 |
| L4 证据 | project-os/证据/、project-os/会话记录/、docs/99_进度/ | 测试输出、会话记录、需求日志、交接 | 仅核验/复盘/交接时读 |

规则：新会话默认只读 L0 + L1 + 相关 L2；修改代码后同步更新对应 L2/L3 并更新文档地图 Updated 行；每个任务结束写 L4 证据。

## 3. 命名规范

- devskill 生成的全部文档一律中文名；仅保留平台约定名：README.md、.gitignore、.devskill、docs/、project-os/。
- 格式：`API-<中文模块名>.md`、`PRD-<中文功能名>.md`、`ADR-NNN-<中文决策名>.md`、`S-YYYYMMDD-NN-<中文主题>.md`、`T-YYYYMMDD-NN-<中文任务名>.md`。
- 中文名 ≤ 12 字，用「做什么」命名；同类文档先查目录，能复用就复用。
- 旧英文名文档迁移用 `git mv` 保留历史；迁移前必须经用户确认。

## 4. 中文书写规范

- 标题层级：`#` → `##` → `###`，最多 4 级，禁止跳级；标题 ≤ 20 字。
- 中文用全角标点；数字、英文、代码用半角；中英文之间、中文与数字之间加空格。
- 日期 YYYY-MM-DD，时间 HH:MM，版本 vX.Y.Z；代码、路径、命令用行内代码包裹。
- 表格必须有表头；空单元格填「-」；任务清单用 `- [ ]` / `- [x]`。
- 代码块必须标注语言（bash/json/python 等）；命令前写「做什么」。
- 文档互引用写完整中文文件名，不写「见上文」。
- 禁止口语化与模糊词；不确定写「待确认」；禁止写入凭据值。

## 5. 维护规则

- 代码是真相：代码变更后，对应文档必须同步，文档跟随代码。
- 更新触发器：需求变化更新 需求日志.md 与 PRD；架构变化写 ADR；功能验收更新 功能清单.md 与 变更日志.md；会话结束更新 项目状态.md 与 交接记录.md。
- 归档而非删除：过时内容移 docs/07_归档/ 或 project-os/任务/归档/；删除仅限空文件与完全重复文件，且须用户确认。
- 提交前验证：任何提交前，测试通过、文档同步、无凭据与对话记录入库。
- 变更审批门：根目录与 docs/ 的合并、移动、归档、删除必须先列出完整计划，经用户确认后执行。
