# 中文书写规范

> 适用：RepoLens-OSS 全部中文文档。本页是[文档规范](文档规范.md)第 4 节的展开版。

## 1. 标题

- 层级只用 `#` → `##` → `###` → `####`，最多 4 级，禁止跳级。
- 标题 ≤ 20 字，用名词短语，不用整句。
- 编号标题统一用阿拉伯数字 + 空格：`## 1. 标题`。

## 2. 标点

| 场景 | 用法 |
|---|---|
| 中文句子 | 全角：，。！？；：「」（） |
| 数字、英文、代码 | 半角：, . ! ? ; : "" () |
| 中英文之间 | 加空格，如「使用 Git 仓库」 |
| 中文与数字之间 | 加空格，如「共 22 个文件」 |
| 省略 | 用「等」，不用 `...` |

## 3. 数字、日期、版本

- 日期 `YYYY-MM-DD`，时间 `HH:MM`，时间范围用 `~`。
- 版本 `vX.Y.Z`。
- 数量必须带单位：「137 个文件」「1.41 MB」「74 个文件哈希通过」。

## 4. 代码与路径

- 行内代码用反引号包裹：`replens/provenance.py`、`python -m pytest tests/ -q`。
- 代码块必须标注语言，并先用一句话说明「这段命令做什么」。
- 路径分隔符：Windows 环境写 `repo\`，跨平台说明写 `repo/`。

## 5. 表格

- 必须有表头，禁用无表头的伪表格。
- 空单元格填 `-`，不写「无」或留空。
- 状态列用固定词：`已完成` / `进行中` / `未开始` / `PASS` / `FAIL` / `待确认`。
- 任务清单用 `- [ ]` / `- [x]`，不用符号模拟。

## 6. 事实表述

本项目的核心原则是**每个判断可被证据证伪或证实**，书写必须反映这一点：

| 禁止 | 应当 |
|---|---|
| 「测试通过」 | 「126 passed / 3 failed / 81 subtests，失败为环境冲突」 |
| 「全部完成」 | 列出验收项与判定表，未通过的写明原因 |
| 「性能良好」 | 给出指标、样本量与测量条件 |
| 「支持 X」 | 说明支持范围与验证边界，如「仅覆盖同步 reset 行为」 |
| 「应该没问题」 | 写「待确认」并说明缺什么证据 |

- 禁止口语化表达（「搞定了」「差不多」）。
- 不确定就写「待确认」，不臆造。
- 禁止写入任何凭据值（token、密码、私钥）。

## 7. 互引用

- 写完整中文文件名：`见 [文档规范](文档规范.md)`，不写「见上文」「见前述章节」。
- 引用历史材料时标注其性质：「历史快照」「历史流水」「不作当前结论」。
