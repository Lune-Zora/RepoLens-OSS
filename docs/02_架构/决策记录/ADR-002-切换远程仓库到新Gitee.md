# ADR-002 切换远程仓库到新 Gitee

> 状态：已采纳
> 日期：2026-10-28
> 关联：[T-20261028-02 新建远端版本管理](../../../project-os/任务/T-20261028-02-新建远端版本管理.md)

## 背景

原远端 `gitee.com/Lune-Zora/repo-oss.git` 的 `main` 停在 `49e186f`，`17fix` 停在 `b085a50`，都落后于当前交付内容；分支列表还残留 7 个 `claude/*` 自动生成分支。
用户指定新仓库 `https://gitee.com/who-ask-my-name-fee/oss1028.git` 作为发布目标。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 继续用旧仓库，把新内容推到 `17fix` | 保留历史 | 旧仓库有残留分支与历史噪音，且用户已指定新仓库 |
| B. 新仓库建库，从头推送 | 干净、单一真源、无历史包袱 | 不继承旧仓库历史 |
| C. 新仓库建库，但保留旧仓库为镜像 | 双保险 | 两处维护，容易再次分裂 |

## 决策

选 **B**。推送前先用 `git ls-remote` 确认新仓库为空（退出码 0、0 行引用），避免覆盖既有内容。

## 后果

- 收益：`main` 与 `repo` 逐字节一致；全新 clone 后测试结果与本地完全相同（126 passed / 3 failed / 81 subtests）。
- 代价：旧仓库历史不再被引用；`repo-oss` 目前仍指向旧远端，尚未迁移。
- 需同步：`project-os/项目状态.md` 登记新远端；`.gitignore` 必须确保 `validation/`（含 Gold 补丁与冻结独立验收）**不入库**，否则真实 Bug 评测可信度归零。
