# ADR-004 评测集口径统一

> 状态：已采纳
> 日期：2026-10-28
> 关联：[评测口径总表](../../05_测试/评测口径总表.md)、[T-20261028-06](../../../project-os/任务/T-20261028-06-三缺口收口.md)

## 背景

5 份评测集字段分成两套：

| 文件 | 原有字段 |
|---|---|
| `dataset.json`、`real_dataset_tqdm.json`、`real_dataset_pypdf.json` | `id` / `category` / `issue` / `expected` |
| `real_dataset_loguru.json`、`real_dataset_extended.json` | 上述 4 项 **+** `project` / `buggy_parent` / `fix_commit` / `test_cmd` |

由此产生两个真实风险：

1. **消费方无从判断能力边界**：拿到 tqdm 数据集做修复评测，会因缺 `fix_commit` 在运行期报错，而不是在读取时被拒绝。
2. **分母可被混算**：可定位正向样本 36 个、可做端到端修复的只有 12 个。若把 36 当修复分母，成功率被系统性低估；若把噪音样本算进正向，又被高估。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 给 3 份定位集补齐 `buggy_parent`/`fix_commit`/`test_cmd` | 表面上字段一致 | **必须编造提交哈希**。这些历史标注本就没有修复信息，编造等于伪造证据 |
| B. 保留现状，只在文档里说明 | 零改动 | 无法机检；文档会漂移；新人仍会踩坑 |
| C. 字段 schema + 文件级种类声明 + 自动校验 | 能力边界可机读；分母口径可验证 | 需新增 schema、清单和校验脚本 |

## 决策

选 **C**，并明确一条不可逾越的红线：**不补造任何缺失的修复信息**。

落地为三件套：

| 文件 | 作用 |
|---|---|
| `eval/datasets/dataset.schema.json` | 样本字段的单一事实源（JSON Schema draft-07） |
| `eval/datasets/datasets.manifest.json` | 文件级 `kind`（`localization` / `repair`）与 `scope` 声明 |
| `scripts/validate_datasets.py` | 读 schema + 清单，做字段校验与业务规则校验 |

同时补了唯一一处**可证实的**字段：给 3 份定位集加 `project`（`dateparse` / `tqdm` / `pypdf`）。该值由清单的 `target_repo` 与标注路径直接确定，不是推断。

## 后果

- 收益：`python scripts/validate_datasets.py` 一条命令给出覆盖表与两个不可混算的分母；`tests/test_datasets.py` 4 条回归测试防止清单漏登记与噪音样本误标。
- 代价：3 份数据集的字节内容变化，其 SHA256 与 `project-os/证据/T-20261025-01-目录与资料整理/路径迁移.json` 记录的迁移时字节不再一致——该记录描述的是当时状态，属历史，不改写。
- 未解决：真实修复样本仍只有 12 个，规模不足以支撑统计显著的自主修复成功率。这是数据缺口，不是本次能修的问题。
