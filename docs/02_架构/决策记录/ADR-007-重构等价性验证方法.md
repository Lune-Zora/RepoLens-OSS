# ADR-007 重构等价性验证方法

> 状态：已采纳
> 日期：2026-10-28
> 关联：[ADR-006 控制端脚本拆分](ADR-006-控制端脚本拆分.md)、[T-20261028-07](../../../project-os/任务/T-20261028-07-阶段化重构与等价性验证.md)

## 背景

拆分 `restore_tqdm_reset_inf.py` 后，我当时用「24 个符号全部存在 + CLI `--help` 正常 + 11 条测试通过」判定拆分成功。

随后在实际跑完整控制流程时，连续暴露两个缺陷：

| # | 缺陷 | 表现 | 单元测试是否发现 |
|---|---|---|---|
| 1 | `pipeline.py` 里 `upstream = upstream._verify_upstream(...)` | 导入名被局部赋值，右侧立即 `UnboundLocalError` | **否**，11 条全绿 |
| 2 | `gitops.py` 漏导入 `urlsplit` | 运行到该分支才 `NameError` | **否**，11 条全绿 |

根因：11 条测试只覆盖 helper 函数和 preflight 失败路径，**主流程 200+ 行从未被执行**。
而「符号存在」和「能导入」都不等于「能跑通」。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 只靠单元测试 | 快 | 已被证伪：本次两个缺陷都没抓到 |
| B. 人工通读 diff | 无需环境 | 256 行控制流，人眼漏检率高 |
| C. 跑真实流程 + 内容归一化逐文件比对 | 覆盖主流程全部 92 个产物 | 每次约 1 分钟，需本地 tqdm 克隆 |
| D. 只比较最终状态字段（PASS/VERIFIED） | 简单 | 粒度太粗，掩盖中间产物差异 |

## 决策

选 **C**，并固化为三步：

1. **建立基线**：在重构前跑一次完整流程，落 92 个产物的哈希清单。
2. **单变量对照**：只替换 `pipeline.py` 一个文件，其余不动，各跑一次。
3. **内容级归一化后比对**：剔除固有随机性后再比较。

归一化必须处理的噪声：

| 噪声源 | 处理 |
|---|---|
| pytest 输出的耗时 `in 0.38s` | 正则替换为 `in <T>s` |
| 随机临时目录 `tqdm_reset_inf_xxxx` | 替换为 `<TMP>` |
| 输出目录路径 | 替换为 `<OUT>` |
| `started_at_unix` / `completed_at_unix` 等时间字段 | 替换为 `<TIME>` |
| 由上述内容派生的 `stdout_sha256`、`raw_log_manifest[].sha256` | 级联归一 |

**关键方法**：必须同时测「同一份代码跑两次」的固有方差。
否则无法区分「重构引入的差异」和「本来就每次不同的差异」。

## 后果

实测结果：

| 对照 | 归一化后不同文件数 |
|---|---|
| 同一份重构代码跑两次（固有方差） | 16 / 92 |
| 重构前 vs 重构后 | 17 / 92 |

逐字段核查差异内容：全部落在 `stdout_sha256`、随机临时目录名、输出路径、时间戳及其级联哈希上；
**材料核验 / 重放一致性 / 修复结论 / 各阶段测试状态 / 补丁内容 / 环境记录等语义字段全部一致**。
结论：重构等价。

新增静态防线 `tests/test_module_hygiene.py`（4 条），用 AST 扫描「导入名被局部遮蔽」与「未定义名字」，
并对两类真实缺陷做过负向验证（能抓到，且正确写法不误报）。

### 代价

等价性验证需要可用的上游仓库克隆与约 1 分钟运行时间，不能只在 CI 里跑。
因此本方法适合**控制端这类产出证据的脚本**，不适用于普通工具函数。
