## 一、问题与场景

目标用户是参与 Python 开源项目的贡献者。一次任务需要找到相关实现、提出修改，并确认修复没有破坏既有行为。本项目围绕这些环节提供辅助工作台，作品形态为 CLI 和可选 Web。

需求定位属于项目设计判断。当前[用户调研](../01_需求/用户调研.md)是提纲，尚无已核实的访谈回收、节省时间或用户满意度数据，本文不虚构需求调研成绩。

## 二、方案与实际流程

入口接收本地仓库、Issue 描述和测试命令。`runner.run_repair` 在模型调用前冻结仓库外独立验收，结合索引、原有测试及轨迹理解问题并选择实际目标；生成计划及当前问题的冻结用例，确认失败后才生成补丁，再执行原有测试、问题用例、独立验收及证据打包。CLI 与 Web 共享编排。验证在临时副本完成，原仓库不被自动改写；页面提供实际 diff 下载供审阅后应用。

- `repo.py` / `indexer.py`：收集源码、文档及仓库信息，建立 AST 符号、调用记录和 SQLite FTS5 索引。
- `retriever.py` / `execution_evidence.py` / `falsify.py`：关键词、调用关系和轨迹辅助定位。相关度是排序信号，不是根因正确概率；轨迹加分不能称为因果证明。
- `issue_understanding.py` / `contracts.py`：先理解原始问题，再核对实际函数及公开返回契约，解释目标、范围与拒答原因。
- `task_tests.py` / `response_schemas.py`：生成并审核行为用例，验证参数及结果结构后冻结；明确输入与期望模式保留调用者来源。
- `planner.py` / `patchgen.py` / `llm.py`：基于检索证据生成计划、结构化补丁及测试反馈重试；严格模式禁止以规则补丁替代模型。
- `executor.py` / `test_adapter.py` / `validation.py`：分别运行修复前后测试，记录测试 ID、有效执行状态和结果；生成检查是辅助回归，不能替代冻结独立验收。
- `provenance.py` / `llm_audit.py`：保存源码、命令、冻结测试、补丁与模型调用记录，并支持材料核验和测试重放。

实现依据：[核心编排](../../replens/runner.py)、[验收逻辑](../../replens/validation.py)、[证据重放](../../replens/provenance.py)。

## 三、模型与开源资源的作用

0.7当前默认使用本机Ollama标签qwen35-9b-unc:latest；页面可选择本机其他模型。模型同时参与问题理解、当前问题用例生成与补丁前审核、计划及补丁生成。目录和文件引用必须与实际源码对应，用例在补丁前冻结；模型生成测试不算独立验收。自动用例可能错误；系统支持调用者明确输入和期望并原样冻结，不将这类样例计作模型生成测试。

本轮在四个没有修复提示的构造仓库上，按本机现有标签/模板配置和相同预算比较：1.5B为0/4、7B为0/4、9B为4/4。9B四项均独立验收VERIFIED、重放PASS，原始源码未改写。四项分别覆盖布尔配置、列表分块、数值闭区间和保持顺序去重。它们是构造任务，不包装为外部真实Bug成绩，失败记录完整保留。详见[通用流程验收](../05_测试/通用修复流程验收.md)。


模型用于生成修改计划与候选补丁；检索排序与测试验收由程序执行。规则生成器只覆盖有限的 strip 模式，不能作为通用智能修复能力。

早期归档日期Demo已验证模型路径为 Ollama 本地兼容 HTTP 接口（`http://127.0.0.1:11434/v1`），实际标签 `qwen2.5-coder:1.5b`，本机 ID `db848539a068`，GGUF / Q4_K_M、约 1.1 GB。正式 Demo 的 5 份原始请求及响应均指向该模型；未用本机另外两个模型完成该次验证。未运行可选 0.5B 训练脚本或采用其输出权重。`11434/v1` 是模型 API 根地址，工作台网页另由项目服务在 `http://127.0.0.1:8000/` 提供。语义向量检索存在可选实现，但本轮没有重跑向量实验，不宣称已验证语义检索带来提升。模型参数规模不作为作品效果证明。

默认规则流程及HTTP客户端使用 Python 标准库；Web、测试和可选transformers/向量后端另有依赖，不能把整个作品称为零依赖。来源、版本和权利边界见[资源清单](../../reports/compliance/open_source_checklist.md)；49项清单中42项在列明使用边界内已核验，3项本轮不适用；本机GGUF来源、Issue/PR文本公开分发边界、Word授权与OpenAI账号合同共4项仍待确认。官方模型许可不自动证明本机转换物来源；不宣称全部许可已完成。

## 四、当前功能与实现边界

| 能力 | 当前代码支持 | 验证边界 |
|---|---|---|
| 仓库导入与索引 | Python AST、文档、FTS5/关键词降级 | 语法错误文件可跳过；索引复用采用源码与文档内容SHA-256；生成材料排除索引 |
| 定位 | 关键词、调用关系、失败轨迹；可选向量融合 | 同名符号身份及语义独立召回仍有限制 |
| 修复 | 规则、HTTP 模型、结构化校验、候选筛选与重试 | 模型输出通过测试才采纳；复杂问题不保证成功 |
| 验收 | 主测试、辅助回归、仓库外冻结独立验收 | VERIFIED 仅针对给定源码和测试范围，不证明所有业务行为正确 |
| 证据 | Schema 2.0 材料核验及重放；HTTP 调用记录 | 哈希与重放用于复核，不是不可篡改的第三方认证 |
| Web | 仓库/定位/计划/修复等 API | 独立浏览器完成自定义仓库修复、独立验收、重放及下载；未验证公网部署 |
| 执行 | 临时副本、命令限制、超时 | 不是操作系统沙箱；不宣称可安全运行任意不可信代码 |

代码中还包含测试翻转统计：`runner.py` 在补丁测试后计算该字段，因此本文不把它描述为事前反事实预测或独立创新效果。

## 六、自主实现与复用价值

本项目实现的组合包括源码证据约束、轨迹辅助检索、候选补丁测试反馈、主测试与独立验收分离，以及可重放材料。这些是可由代码核对的设计特点，不宣称首次提出，也不在没有同预算实验时声称优于其他智能体。

## 七、风险与限制

当前主要支持Python与pytest/unittest；复杂仓库环境、完整符号身份、大仓库资源开销、跨语言与跨机器验证仍有缺口。许可证识别属于规则辅助，不是授权结论。临时副本执行不等于容器或权限隔离。

除本轮已归档结果外，历史文档数字、用户反馈、训练脚本或PR材料不能自动作为当前完成证明。LoRA脚本与训练数据的存在不代表本次使用了自训模型，更不能推导微调有效。
