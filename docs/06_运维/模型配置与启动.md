# 模型配置与启动（0.7）

更新：2026-10-30。本次增加问题理解、补丁前冻结的行为用例、原有测试保护、独立构造任务和逐请求模型选择。

## 启动工作台

需要两个本地服务：Ollama负责模型，RepoLens负责网页。先打开Ollama应用；如果11434端口没有服务，可在另一个终端运行 `ollama serve`。本机现有模型目录为 `E:\fqdeepseek\ollama\models`；若新终端未识别已有模型，可先设置 `$env:OLLAMA_MODELS='E:\fqdeepseek\ollama\models'` 再启动。已有服务时不重复启动。

```powershell
Set-Location -LiteralPath 'E:\osspj\人工智能\repo'
python -m pip install -c constraints.txt -e '.[web,test]'
python scripts/start_web.py
```

打开 http://127.0.0.1:8000/，保持启动进程运行。Ollama模型API根地址是 http://127.0.0.1:11434/v1，直接在浏览器打开API根地址可返回404；它不是工作台。模型列表检查用 /v1/models。

当前启动默认模型为本机 `qwen35-9b-unc:latest`。可用 `python scripts/start_web.py --model qwen25-7b-unc:latest` 设置启动默认值，也可在网页模型下拉框选择已安装模型；网页选择只作用于该次计划/修复请求，不修改其他请求的环境变量。

早期归档的 `demo-llm-20261030-022020` 实际使用 `qwen2.5-coder:1.5b`，ID db848539a068。本次默认变化不改写旧实验记录。三个本地标签是本机实际标识，不据此声称其与官方发布权重完全一致；原始来源核验仍有待确认项。

## 在工作台测试

1. 可选一个“独立构造的验证任务”，界面会填入仓库、问题及仓库外验收路径；这些是明确标注的构造任务，不是外部真实Issue基准。
2. 使用自己的项目时，选择实际仓库并输入现象、具体输入和预期行为，支持中文。问题必须对应该仓库的功能。
3. “检索并生成计划”展示问题理解、实际目标、检索表达和无法定位时的原因。大仓库目录有预算上限，截断会披露。
4. “完整闭环”在模型模式下先生成并审核当前问题的行为用例，在补丁前冻结；运行仓库现有测试和这些用例。原测试存在其他失败时会单列，不能把它们说成全仓库已通过。
5. 只有模型测试通过而没有独立验收，结论仍为UNVERIFIED。独立验收JSON在仓库外提供，冻结后不进入模型输入或候选重试反馈。
6. 完成后检查修改范围、逐测试结果和diff，再点击证据重放并下载报告和补丁。验证在临时副本完成，不自动修改原仓库；审阅后再应用导出的diff。VERIFIED仅覆盖列出的测试行为。

## 明确输入与期望（可选）

自动测试设计可能遗漏边界或给出错误预期，系统会保留失败，不能靠修改已有失败记录显示成功。工作台“完整闭环”中可展开“提供明确的输入与期望结果”，例如分块函数的复现输入：

```json
[{"args": [[11, 12, 13], 2], "expected": [[11, 12], [13]]}]
```

这表示函数接收两个参数：列表和大小。单个目标函数可省略path和symbol；多个目标需明确实际文件与函数名。预期异常使用raises，例如ValueError。提供的样例原样冻结，模型不会改写；报告会标明这是调用者提供的样例，不算模型自动生成测试，也不能替代独立验收。

CLI可用 `--behavior-examples <样例数组.json>`。未提供样例时，程序自动设计测试；若第一次问题用例全部通过，会保留这些检查，最多再设计一轮新输入。新输入可参考实现，但预期值设计与审核只看需求、接口和公开测试，独立验收内容始终不参与。

## 标准CLI

普通CLI和直接uvicorn不自动读取.env。在PowerShell明确设置：

```powershell
$env:REPLENS_LLM_BASE_URL = 'http://127.0.0.1:11434/v1'
$env:REPLENS_LLM_MODEL = 'qwen35-9b-unc:latest'
$env:REPLENS_REQUIRE_LLM = '1'
$env:REPLENS_LLM_N_CANDIDATES = '2'
$env:REPLENS_LLM_TIMEOUT = '180'
$env:REPLENS_LLM_MAX_TOKENS = '2200'
$env:REPLENS_LLM_REASONING_EFFORT = 'none'
$env:REPLENS_LLM_MAX_REPAIR_ROUNDS = '1'
python -m replens run examples/independent_tasks/repositories/config_values --issue '布尔值字符串前后有空白时也应解析，其他内容仍报ValueError' --auto-patch --acceptance-suite examples/independent_tasks/validation/config_values.json --require-verified
```

`run --model <标签>`可覆盖本次请求模型。模型模式的主测试由仓库测试目录和新任务测试共同组成，实际命令保存在报告test_command，用户输入命令保存在requested_test_command。此路径需要pytest；不能把整套运行依赖称为零依赖。

## 配置入口

| 入口 | 配置来源 |
|---|---|
| 普通CLI / 直接uvicorn | 进程环境变量 |
| scripts/llm_env.py | 环境变量 > .env > 默认值；自检不导出到父终端 |
| scripts/start_web.py | 同上；显式加载后启动服务，--model可覆盖 |
| scripts/run_llm_demo.py | 同上；强制严格模型模式，保留旧Demo完整证据入口 |

三个配置脚本读取九个字段：BASE_URL、MODEL、API_KEY、N_CANDIDATES、REQUIRE_LLM、TIMEOUT、MAX_TOKENS、REASONING_EFFORT、MAX_REPAIR_ROUNDS，均使用REPLENS_LLM_前缀，严格模式字段为REPLENS_REQUIRE_LLM。TRACE_DIR、provider、embedding配置需通过进程环境设置，不在这九项中。启动脚本会为Web调用创建独立追踪目录。

本地服务通常无需API key；若设置了通用OPENAI_API_KEY，普通客户端会按现有逻辑读取。不要把密钥写入提交材料。GET模型列表成功或页面“已配置”不能替代实际推理验证。

## 运行预算与限制

默认每轮2个候选、最多额外1轮修复，HTTP调用180秒，输出预算2200。reasoning_effort=none用于该本地接口的推理输出配置；早期9B在短预算下曾只返回推理内容而没有最终JSON，该失败记录已保留。切换模型后仍需实际测试，不能由参数规模推断一定正确。

可选向量检索只在明确使用的入口尝试；网页的问题理解流程使用LLM与实际源码目录，不把“安装了向量库”显示成“向量权重已可用”。模型仍可能理解或生成错误；测试生成失败、参数绑定错误、目标未复现、候选越过范围或验收失败都会保留失败状态。
