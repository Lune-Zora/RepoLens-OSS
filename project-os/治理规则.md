# 项目治理规则

> 本文件定义「怎么在这个项目里工作」。技术规范（语言/框架/编码）见 docs/02_架构/规则说明.md。规则变更必须记 project-os/决策日志.md。文件命名遵循 devskill templates/NAMING.md，书写遵循 devskill templates/DOC_STYLE.md。

## 1. 工作方式
- 使用 devskill：澄清 → 计划 → 实现 → 验证 → 记录 → 复盘。
- 新会话先读：项目状态.md → 交接记录.md → 决策日志.md → docs/文档地图.md（继续会话再读最近 project-os/会话记录/S-YYYYMMDD-NN-中文主题.md）。
- 防遗忘：关键规则与当前任务用 fact_register 钉住；功能完成立即回填记录；不依赖对话记忆。

## 2. 记录规则（默认执行，全部有模板）

2026-10-25 起：`项目状态.md` 是当前状态的唯一入口；根 `ROADMAP.md` 是未来任务与验收清单；`docs/99_进度/待办.md` 只导航。执行日志、变更日志和交接记录按日期保留历史，不维护另一份当前清单。历史功能快照明确标注日期。新规则见决策 D-003。

| 记录 | 位置 | 时机 |
|---|---|---|
| 需求日志 | docs/99_进度/需求日志.md | 提出即记，完成回填 done |
| 会话记录 | project-os/会话记录/S-YYYYMMDD-NN-中文主题.md | 会话开始建，过程中追加，结束回填 |
| 任务详情 | project-os/任务/T-YYYYMMDD-NN-中文任务名.md | 大需求（预计 >30 分钟）开工前 |
| 验收证据 | project-os/证据/T-YYYYMMDD-NN-中文任务名/ | 验证/验收时落盘 |
| 待办导航 | docs/99_进度/待办.md | 仅链接状态与 ROADMAP，入口变化时更新 |
| 功能历史 | docs/99_进度/功能清单.md | 历史快照保留；新验收回写项目状态与需求记录 |
| 变更日志 | 变更日志.md | 版本/任务完成追加 |
| 决策 | project-os/决策日志.md | 规则/架构变化立即记 |
| 状态 | project-os/项目状态.md | 会话结束更新 |
| 交接 | project-os/交接记录.md | 暂停/结束/接手时 |

## 3. 工程纪律
- 做功能：先写需求与验收标准 → 小步实现 → 测试 → 更新文档。
- 改 bug：先写失败测试复现 → 修复 → 测试全绿。
- 重构：先确认测试覆盖 → 小步重构 → 每步回归。
- 禁止：删除/弱化失败测试、跳过测试、手写成熟库功能、改完不更新文档。

## 4. 变更管理
- 代码变更 → 变更日志.md；规则变更 → project-os/决策日志.md；文档分级 → devskill templates/DOC_LEVELS.md；文件命名 → devskill templates/NAMING.md；中文书写 → devskill templates/DOC_STYLE.md。

## 5. 红线
- 不覆盖用户内容；不自动清理（需用户确认）；不臆造事实；不记凭据值。
