## 缺口 2：评测集字段口径不一

### 问题实质

5 份数据集字段分两套：3 份只有 `id/category/issue/expected`，2 份另含 `project/buggy_parent/fix_commit/test_cmd`。
消费方无法从数据判断能力边界；「36 个正向样本」与「12 个可修复样本」极易混算。

### 解法与证据

| 新增文件 | 作用 |
|---|---|
| `eval/datasets/dataset.schema.json` | 样本字段单一事实源 |
| `eval/datasets/datasets.manifest.json` | 文件级 `kind` / `scope` 声明 |
| `scripts/validate_datasets.py` | schema + 业务规则校验，输出覆盖表 |
| `tests/test_datasets.py` | 4 条回归测试 |
| `docs/05_测试/评测口径总表.md` | 口径与局限的唯一来源 |

覆盖表实测输出：

| 文件 | 种类 | 样本 | 正向 | 可修复 |
|---|---|---|---|---|
| dataset.json | localization | 25 | 20 | 0 |
| real_dataset_tqdm.json | localization | 5 | 2 | 0 |
| real_dataset_pypdf.json | localization | 5 | 2 | 0 |
| real_dataset_loguru.json | repair | 4 | 4 | 4 |
| real_dataset_extended.json | repair | 10 | 8 | 8 |

- 可定位正向样本合计 **36**；可端到端修复样本合计 **12**。两者分母不同，禁止相除。
- 负向验证 **10 项用例全部被捕获**（噪声带 expected、正向 expected 为空、修复字段半有半无、id 重复、标注格式非法、非法枚举、未声明字段、缺必需字段、commit 非十六进制等）。

### 数据改动与边界

- 仅补 `project` 字段（`dateparse` / `tqdm` / `pypdf`），值由清单 `target_repo` 与标注路径确定。
- **未补造任何修复提交**。tqdm/pypdf 仍为 `localization` 类，不能计入修复成功率。
- 3 份数据集字节变化后，其 SHA256 与 `路径迁移.json` 记录的历史字节不再一致；该记录描述当时状态，不改写。

## 缺口 3：38 KB 单文件脚本

### 问题实质

`scripts/restore_tqdm_reset_inf.py` 695 行 / 24 个顶层符号，`run()` 独占 256 行，且它是已交付证据链的控制端。

### 解法与证据

用 AST 按行范围机械切片生成 10 个模块（函数体逐字保留，不手工转录），入口保留为兼容层。

| 模块 | 行数 | 职责 |
|---|---|---|
| `errors.py` | 6 | `RestoreError` |
| `constants.py` | 39 | 提交哈希、路径、测试命令 |
| `common.py` | 16 | 哈希、路径判断、写入 |
| `gitops.py` | 118 | Git 命令、日志、worktree、补丁、只读审计 |
| `suites.py` | 47 | 套件执行与状态比对 |
| `upstream.py` | 88 | remote / 许可 / 提交 / 目标文件核验 |
| `environment.py` | 46 | 环境冻结 |
| `pipeline.py` | 257 | 主流程编排 |
| `cli.py` | 42 | 命令行入口 |
| `__init__.py` | 73 | 重导出 |
| `restore_tqdm_reset_inf.py` | 73 | 兼容入口 |

契约核验：

| 项 | 结果 |
|---|---|
| 原 24 个符号 | 24/24 保留 |
| 原 9 个常量 | 9/9 保留 |
| `run(args)` / `main(argv=None)` 签名 | 不变 |
| CLI `--help` | 参数与描述一致 |
| 测试 | 原 7 条通过 + 新增 4 条兼容性 = 11 条通过 |

### 顺带修正的假通过

拆分后 `patch.object(control, '_verify_upstream')` 与 `patch.object(control, '_add_worktree')` 变成空操作，但相关测试**仍然通过**——被断言的对象从未被调用。
已改为 patch 子模块，并新增 `test_patching_gitops_intercepts_license_lookup` 断言补丁确实拦截到调用。

### 未做

`run()` 仍为 256 行。经复核，它**有明确阶段边界**（`record['stage'] = ...` 共 8 处：preflight / upstream-verification / environment / buggy-worktree / buggy-baseline / gold-validation / cross-worktree-replay / complete）。

> **更正**：本节初稿曾写「源码无阶段分隔标记」，该结论错误——当时只检索了注释型标记，未检索 `record['stage']` 赋值。实际拆分可行。

止步的真实理由：8 个阶段共享约十个可变状态（`managed` / `execution_repo` / `worktrees` / `buggy` / `replay` / `source_before` / `record` / `logs` / `output` / `repo`），拆函数需显式穿透或引入上下文对象；该脚本产出已交付证据链，改错代价是全链路重跑。
故判定为「**可做但本次不做**」，属未做的技术债，**不是阻塞项**。
