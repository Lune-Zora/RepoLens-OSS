## 一、问题与场景

目标用户是参与 Python 开源项目的贡献者。一次任务需要找到相关实现、提出修改，并确认修复没有破坏既有行为。本项目围绕这些环节提供辅助工作台，作品形态为 CLI 和可选 Web。

需求定位属于项目设计判断。当前[用户调研](../01_需求/用户调研.md)是提纲，尚无已核实的访谈回收、节省时间或用户满意度数据，本文不虚构需求调研成绩。

## 二、方案与实际流程

入口接收本地仓库、Issue 描述和测试命令。`runner.run_repair` 在检索前冻结仓库外独立验收材料，随后建立索引、复现失败、提取轨迹、检索代码、生成计划和补丁、执行测试、独立验收及打包。CLI 与 Web 的完整修复入口共享此编排。

- `repo.py` / `indexer.py`：收集源码、文档及仓库信息，建立 AST 符号、调用记录和 SQLite FTS5 索引。
- `retriever.py` / `execution_evidence.py` / `falsify.py`：关键词、调用关系和轨迹辅助定位。相关度是排序信号，不是根因正确概率；轨迹加分不能称为因果证明。
- `planner.py` / `patchgen.py` / `llm.py`：基于检索证据生成计划、结构化补丁及测试反馈重试；严格模式禁止以规则补丁替代模型。
- `executor.py` / `test_adapter.py` / `validation.py`：分别运行修复前后测试，记录测试 ID、有效执行状态和结果；生成检查是辅助回归，不能替代冻结独立验收。
- `provenance.py` / `llm_audit.py`：保存源码、命令、冻结测试、补丁与模型调用记录，并支持材料核验和测试重放。

实现依据：[核心编排](../../replens/runner.py)、[验收逻辑](../../replens/validation.py)、[证据重放](../../replens/provenance.py)。

## 三、模型与开源资源的作用

模型用于生成修改计划与候选补丁；检索排序与测试验收由程序执行。规则生成器只覆盖有限的 strip 模式，不能作为通用智能修复能力。

当前已验证模型路径为 Ollama 提供的兼容 HTTP 接口及 `qwen2.5-coder:1.5b`。语义向量检索存在可选实现，但本轮没有重跑向量实验，不宣称已验证语义检索带来提升。模型参数规模不作为作品效果证明。

默认规则流程及HTTP客户端使用 Python 标准库；Web、测试和可选transformers/向量后端另有依赖，不能把整个作品称为零依赖。来源、版本和权利边界见[资源清单](../../reports/compliance/open_source_checklist.md)；清单仍有待核验条目，不能宣称全部第三方许可已完成认证。

## 四、当前功能与实现边界

| 能力 | 当前代码支持 | 验证边界 |
|---|---|---|
| 仓库导入与索引 | Python AST、文档、FTS5/关键词降级 | 语法错误文件可跳过；索引复用采用路径、mtime 和大小的元数据指纹，不是内容哈希 |
| 定位 | 关键词、调用关系、失败轨迹；可选向量融合 | 同名符号身份及语义独立召回仍有限制 |
| 修复 | 规则、HTTP 模型、结构化校验、候选筛选与重试 | 模型输出通过测试才采纳；复杂问题不保证成功 |
| 验收 | 主测试、辅助回归、仓库外冻结独立验收 | VERIFIED 仅针对给定源码和测试范围，不证明所有业务行为正确 |
| 证据 | Schema 2.0 材料核验及重放；HTTP 调用记录 | 哈希与重放用于复核，不是不可篡改的第三方认证 |
| Web | 仓库/定位/计划/修复等 API | 本机服务和模型计划已实测；完整浏览器流程尚未验收 |
| 执行 | 临时副本、命令限制、超时 | 不是操作系统沙箱；不宣称可安全运行任意不可信代码 |

代码中还包含测试翻转统计：`runner.py` 在补丁测试后计算该字段，因此本文不把它描述为事前反事实预测或独立创新效果。

### 5.3 数据资产

6份数据集共有136个定位正向描述，其中包含20个Demo描述；修复类候选条目112个，包含3个弱描述。112条记录含 fail_pass=true 与 targeted 字段，本轮校验了字段和schema，没有重新运行全部上游测试，更没有让模型修复这112条。

数据量不等于成功修复量，也不自动等于相互独立的Bug数。统计成功率必须披露实际执行样本、环境问题、排除项与预算，不能把112直接当成本次模型实验的分母。详见[评测口径总表](../05_测试/评测口径总表.md)。

## 六、自主实现与复用价值

本项目实现的组合包括源码证据约束、轨迹辅助检索、候选补丁测试反馈、主测试与独立验收分离，以及可重放材料。这些是可由代码核对的设计特点，不宣称首次提出，也不在没有同预算实验时声称优于其他智能体。

代码、测试、评测脚本、配置说明和证据可用于复核该流程。[维护计划](../../ROADMAP.md)与[贡献规范](../../CONTRIBUTING.md)已提供；公开下载链接、最终发布包及评审期访问权限仍需提交前实际检查。没有在本材料中提供可核验的新上游PR，历史参考补丁不包装为已合并社区贡献。

## 七、风险与限制

当前主要支持Python与pytest/unittest；复杂仓库环境、完整符号身份、大仓库资源开销、跨语言与跨机器验证仍有缺口。许可证识别属于规则辅助，不是授权结论。临时副本执行不等于容器或权限隔离。

除本轮已归档结果外，历史文档数字、用户反馈、训练脚本或PR材料不能自动作为当前完成证明。LoRA脚本与训练数据的存在不代表本次使用了自训模型，更不能推导微调有效。
