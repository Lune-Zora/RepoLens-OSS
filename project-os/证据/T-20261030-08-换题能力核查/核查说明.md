# 换题能力核查

日期：2026-10-30。核对代码并实际执行6组检索、1次不同问题的Web模型计划调用。未修改业务代码或Demo，不新增与用户问题配套的布尔解析实现。

## 截图中的失败

目标仓库是examples/demo_repo，dateparse包共10个函数，涉及日期解析、格式化、区间、日期运算、闰年和周末，没有布尔字符串解析器。对“布尔值字符串（true/false）前后有空格时解析失败”，关键词检索实际返回空证据/insufficient_evidence=true。不能要求定位器在此仓库里找到不存在的布尔解析实现。当前页面又没有充分解释任务范围和拒答原因。

## 固定规则和实际模型

- replens/patchgen.py:227的RulePatchGenerator确实写了STRIP_HINTS集合，规则补丁只处理有限空白模式。这是固定模式兜底，不是通用模型修复。
- LLMPatchGenerator会把用户issue、检索代码和反馈发给模型，结构化校验后测试候选，不是只按题目返回预存答案。
- replens/planner.py:127在没有evidences时直接返回证据不足计划，不会进入后面的模型调用。安装并配置LLM不等于每个输入都会经过模型语义理解。
- replens/retriever.py:39的中文按连续片段保留，不做中英翻译；约264行使用关键词命中阈值。英文代码面对纯中文描述容易在调用模型前被挡住。
- examples/demo_repo/src/dateparse/parser.py:21明确写着call s.strip() before parsing。其他Demo函数也有问题提示，所以这不是未见真实问题的盲测，不能据此宣称复杂真实Bug泛化。
- 本轮未加载向量模型；勾选混合检索不自动证明向量推理真正生效，且混合检索代码也保留关键词拒答条件。

结论：不是所有结果写死；但规则修复确有固定模式，当前演示与验证偏向特定Demo，中文/同义改写与跨仓库泛化仍有实质缺口。能运行模型闭环不足以称为成熟通用自动修复工具。

后续应先改进仓库范围提示与拒答原因，再做通用查询理解/检索与真实向量状态，保留英文标识和中文描述的多种表达测试。泛化验证应使用未预写答案提示的独立仓库任务，配套针对该问题的失败测试、受改范围回归与独立验收。不得为通过当前质疑临时添加专门布尔解析Demo再把它称为既有通用能力，也不能继续用日期专用测试判定其他问题已经修好。
