# 2026-10-26 第一阶段验收记录

## 本轮实现

1. JSON Schema 2.0 与清晰目录：源码逐文件/聚合 SHA-256、Python/依赖版本、测试命令/超时、补丁内容、前后结构化结果。
2. 接入现有 `examples/acceptance/demo.json`，生成前冻结；完整代码、命令与冻结哈希进入证据包，不进入检索、计划或候选生成。
3. 核验必需 JSON/Markdown/补丁/套件文件、哈希、源码及环境，并核对报告与套件关系。
4. 在干净副本中重放主测试、生成辅助检查和独立验收的前后结果；复用统一验收逻辑比较测试身份和状态。
5. CLI、Web 和 Markdown 分别表达材料核验、重放一致性与修复结论；打包异常可见，旧包标记 LEGACY。
6. 专项测试、正常 Demo 重放、前端检查、格式与使用文档完成。Git 上传按用户要求暂缓。

## 实测

- Python 3.13.6；`19` 项专项检查中 `18` 项通过，`1` 项真实 HTTP 检查因缺少 FastAPI/HTTPX 跳过。详见 [专项验证](专项验证.json)。
- 新增测试使用现有正常 Demo，涵盖完整材料、冻结隔离、三组重放、源码移动、不同运行记录、无补丁、普通生产补丁无法匹配源码、打包 I/O 失败、CLI 格式/退出码及 Web handler。
- 主测试：修复前 2 PASS / 1 ERROR，修复后 3 PASS；独立验收：修复前 2 PASS / 1 ERROR，修复后 3 PASS；辅助检查同样由 2 PASS / 1 ERROR 转为 3 PASS。
- Demo 材料核验 PASS、重放一致性 PASS、修复 VERIFIED，三组 before/after 均一致。详见 [Demo 重放](Demo重放.json)。
- 无独立材料时主测试成功保持 UNVERIFIED，重放一致不会提升结论。普通无法应用的生产补丁保持 FAILED，没有补丁保持 NO_PATCH。
- Node.js 语法及真实前端函数的 DOM/fetch 桩检查通过，详见 [前端检查](前端检查.json)；不是浏览器或 HTTP 集成验证。
- JSON Schema 文件通过 JSON 解析与本地引用检查；本机未安装 jsonschema，未使用第三方 Schema 验证器。运行时字段与材料一致性由核心实现核验。

## 范围

修改和测试在既有授权工作区副本完成，不写桌面原目录、不调用审批、不创建额外完整仓库副本。交付需由用户同步变更文件至桌面 `repo` 后生效。

本轮没有运行完整历史回归、真实模型、真实上游 Bug 实验、真实 HTTP 或干净检出验证。离线规则 Demo 结果不能作为真实模型修复率。后续先补 Web 依赖下的 HTTP 验证和交付回归，再开始真实 Bug 样本恢复。
