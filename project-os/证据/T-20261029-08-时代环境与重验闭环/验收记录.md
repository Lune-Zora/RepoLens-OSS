## 五、过程中踩到并修掉的坑

| 坑 | 现象 | 根因 | 修法 |
|---|---|---|---|
| venv 复用不重建 | 一条好样本被判「修复后测试未通过」 | 旧 venv 残留 pyOpenSSL 与新装 cryptography 不配（`GEN_EMAIL` 缺失） | 指纹加入 `BUILDER_VERSION`，不符即删库重建；提供 `era_env.reset()` |
| 运行期依赖抽取 | 候选全部报 `ModuleNotFoundError: charset_normalizer` | 只按 `install_requires` 切块，遇到 `install_requires=requires` 取不到 | 支持 `requires=[...]` 变量写法；并排除 `('pytest-args=', ...)` 这类选项串 |
| 锁与提交版本冲突 | pip 报解析冲突 | 锁钉 1.26.20，提交声明 `<1.24` | 锁文件优先（`merge_requirements`） |
| pytest 输出走管道 | 超时失效、整批挂住 | 孙进程持管道句柄 | 输出写文件 + Popen + 杀进程树 + `-u` |
| 节点 id 缺类名 | 「not found」被记成「修复后未通过」 | pytest 节点 id 是 文件::类::方法 | AST 父链拼类名 |
| 同名符号归属 | 标注落在同名的另一个函数上 | 按名字取第一处 | 取旧文件里同一位置的同名符号 |
| 策展集描述被覆盖 | 重验时把手写描述改成提交标题 | `repair_annotations.py` 无条件重算 issue | 新增 `--verify-only`：只重验不动标注 |
| 噪声样本卡住重验 | `KeyError: fix_commit` | 重验流程假设每条都是修复样本 | 无修复提交的样本标记「跳过」，不计入通过率 |
| 环境按解释器混用 | 旧解释器建的环境找不到 | venv 目录名只按当前解释器打标签 | 目录带 `pyXY` 标签；`--python` 建、`REPLENS_ERA_PY_TAG` 复用 |

## 七、边界与遗留

1. **Python 版本不随时代切换**：本机只有 3.10。2018–2019 的提交能跑是运气，不能外推；要真正复刻需补旧解释器。
2. **首次构建需联网**：venv 建好后离线可复用；离线场景应预置 venv 并设 `REPLENS_ERA_ENVS`。
3. **时代锁只有一代**（`urllib3-1`）；新增时代按同格式补锁文件。
4. **2 条 requests 弱描述未升级**（`79c4a017fe` / `38f3f8ecb9`）：GitHub 未鉴权接口已限流（60 次/小时），未取到 PR 原文；已登记进判定文件，未改写。
5. **重验耗时**：串行 100 条约 9.5 分钟；并发能压到 ~7 分钟，但历史用例（pypdf / click）在并发下偶发变慢，故默认串行。
