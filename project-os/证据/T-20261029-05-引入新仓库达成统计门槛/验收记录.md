## 一、关键发现：验证测的是已安装包，不是被修改的源码

首次对 click 挖掘：**3 条候选全部失败**，理由清一色「修复后测试未通过」。

查证：click 是 **src 布局**（`src/click/`）且已安装进 site-packages。
在 worktree 里跑 pytest 时，`import click` 解析到 **site-packages 的已安装版本**，
补丁修改的 `src/click/*` 根本没有被执行。

### 为什么历史样本没受影响

用探针在真实 worktree 中打印 `__file__` 实测：

| 仓库 | 布局 | 未设 PYTHONPATH 时导入的是 |
|---|---|---|
| tqdm | 扁平 | worktree 源码 ✓ |
| loguru | 扁平 | worktree 源码 ✓ |
| click | src | **site-packages** ✗ |
| click（设 PYTHONPATH 后） | src | worktree `src/click` ✓ |

pytest 的 prepend 导入模式会把测试文件上溯到的根目录插入 `sys.path[0]`。
扁平布局下这个根目录正好是 worktree 根，源码自然优先；src 布局下根目录不含包，于是回落到 site-packages。

**结论**：tqdm / pypdf / loguru 的历史样本不受影响，无需重验。

修复：`_worktree_env()` 把 worktree 根与 `worktree/src` 前置进 PYTHONPATH。
**同批候选 0/3 → 4/4**。

## 二、把上一轮的人工发现固化为自动检查

第一轮的重复样本（`#55`/`#56`）是靠人眼对比 tree 哈希发现的。本轮加了两项自动检查：

| 检查 | 内容 | 本轮抓到 |
|---|---|---|
| C7 | 必须改动至少一个非测试源码文件 | click 2 条「只改测试」 |
| C8 | 补丁内容哈希不得重复 | click fish completion 一对重复 |

**C8 用补丁内容哈希而非 tree 哈希**：cherry-pick 或分支合并会让 tree 不同但补丁相同，
click 上正好遇到这种情况——用 tree 会漏判。

同时修正了重复组处理：只标记「非首条」为重复，保留一条，避免整组被裁掉。
