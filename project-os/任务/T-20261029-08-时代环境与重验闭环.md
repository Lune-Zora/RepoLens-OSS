## 目标

解决「七」留下的三项遗留：

| # | 遗留 | 上一轮的结论 | 本轮要回答的问题 |
|---|---|---|---|
| ① | requests 其余候选受 urllib3 版本限制 | 「装依赖没用」，贡献 1 条 | 到底缺什么？能不能按时代建环境？代价多大？ |
| ② | 剩余 8 条弱描述是上游原文 | 「不改写」，保留 8 条 | 这 8 条真的是上游写得差，还是我们削出来的？ |
| ③ | `repair_annotations.py` 只改标注、不重验 | 「重跑代价高」 | 改了标注却没有 fail→pass 证据，凭什么说样本可用？ |

## 设计判断

| 项 | 原设想 | 实际选择 | 原因 |
|---|---|---|---|
| ① 环境 | 为每个候选建一套环境 | **按依赖声明选画像 + 共用锁文件** | 11 条候选只落在两代（urllib3 1.x / 2.x）；按候选建 11 套纯属浪费 |
| ① venv 位置 | 放仓库里 | **用户缓存 + 环境变量覆盖** | 同一代环境跨仓库共享；几万个小文件不该塞进工作区 |
| ① pytest 版本 | 完全复刻该时代的 6.2.5 | **7.4.4 + 锁文件头注明取舍** | 6.2.5 与 py3.10 插件生态不稳；定义这个时代的约束是 urllib3 的 API |
| ② 处理方式 | 改写措辞 | **换出处（正文 / issue 标题 / PR 正文），并记录 URL** | 改写会让描述不再来自上游；换出处仍是上游原文且可核查 |
| ② 触发条件 | 启发式判弱就换 | **只在人工判定为 weak 时换** | 启发式会把「pandas>=3 & negative format_interval」这类短而合格的标题换坏（实测踩到） |
| ③ 重验 | 可选开关 | **默认开启，失败不落盘** | 留下「没验证也能写数据集」的口子，等于没有闭环 |

## 实现

### 一、时代环境 `replens/era_env.py`

- `select_profile()`：读**父提交**的 `setup.py` / `setup.cfg` / `requirements*.txt` 的 urllib3 上界；上界 < 2 或测试代码未加守卫地导入 `SNIMissingWarning` → `urllib3-1`，否则 `modern`。
- `runtime_specifiers()`：取该提交 `install_requires`（支持 `requires=[...]` 写法）；只认「包名 + 比较符 + 数字」，避免把 `('pytest-args=', 'a', ...)` 当依赖。
- `merge_requirements()`：锁文件已钉版本的包以锁为准，否则 pip 解析冲突（`1.26.20` vs `<1.24`）。
- `ensure()`：建/复用 venv（指纹 = 锁 + 合并后的运行期依赖），写 `replens-era.json` 记录版本快照。

### 二、验证器的两处缺陷

| 缺陷 | 表现 | 修法 |
|---|---|---|
| 节点 id 少类名 | `class TestRequests` 的方法只写函数名 → `not found`（退出码 4），被记成「修复后测试未通过」 | `_test_node_spans()` 沿 AST 父链拼 `文件::类::方法` |
| 输出走管道 | 孙进程持管道句柄，超时后仍等 EOF；且 `run()` 只杀 pytest 本身 | 输出写文件 + `Popen.wait(timeout)` + `taskkill /T` 杀整棵树 + `-u` 不缓冲 |

### 三、描述出处 `eval/curation/issue_upgrade.json`

- 结构：`fix_commit` / `issue` / `source`（`upstream_issue` / `upstream_pull`）/ `ref` / `url` / `fetched_at` / `note`。
- 数据字段：`issue_source`、`issue_quality`，写入 schema，校验器与复核器都据此取证。

### 四、重验 `scripts/repair_annotations.py`

- 默认 `--verify`；`--no-verify` 只重算标注（排查用）。
- 验证现场由 parent/commit 现算，不依赖当年挖出来的 patches 目录；超时重试一次（区分环境抖动与真超时）。
- 写回 `fail_pass` / `verified_at` / `env_profile` / `validation_scope`，并把 `test_cmd` 校正为真正跑通的命令。
- 任一失败 → 不写文件、非零退出。

## 边界

- Python 版本不随时代切换：本机只有 3.10，2018-2019 的提交能跑是运气，不能外推。
- 首次构建时代环境需要联网；离线应预置 venv 并设 `REPLENS_ERA_ENVS`。
- 时代锁只有 `urllib3-1` 一代；新增时代需按同格式补锁文件。
- requests 另有 2 条弱描述因 GitHub 未鉴权限流（60 次/小时）未能取到 PR 原文，已登记在判定文件里，未改写。
