# 任务 T-20261007-03：反馈顺序修复

> 文件命名：project-os/任务/T-20261007-03-反馈顺序修复.md

## 需求（做什么 / 为什么）
- 背景：审查报告 6.4：cmd_run 顺序为检索→计划→生成测试→补丁→之后才提取 traceback 重检索，首轮补丁未利用失败轨迹。
- 目标：改为先复现失败→提取运行证据→检索与计划→生成补丁，首轮即使用失败轨迹。
- 不做（范围外）：不重构 CLI 与 Web 为同一服务（列为后续），本次先修 CLI 编排顺序。

## 实现思路
- 方案：cli.cmd_run：先 run_test_suite 无补丁复现 before，parse_traceback_frames 提取 hints，再检索与计划，最后 auto_patch_loop；Web 后续同步。
- 备选方案与否决原因：保持最小改动，优先修复行为缺陷，不重写模块。
- 关键假设：核心包 replens/ 保持零第三方依赖；当前解释器可跑 unittest。
